HANDOFF — SARE (Ghidra pipeline บน GitHub Actions) สำหรับโปรเจกต์ ProMenu (tanakorn1680/Menusan-Mod.so)
อัปเดต: 2026-10-25 | เกม: GTA San Andreas Android 2.10 (com.rockstargames.gtasa) arm64 | เมนูต้นแบบ: ARM Cheat Menu v2.32 (libCheatMenu64.so)

== เป้าหมาย ==
ProMenu ต้องมีฟังก์ชันเท่าเมนู ARM Cheat Menu v2.32 ทั้งหมด (ยึดเวอร์ชันใหม่) ; ข้อมูลที่ต้องใช้คือ "โค้ดจริง" ของเมนูต้นแบบ (ฟิลด์ struct, ค่าคงที่, hook,
สัญลักษณ์เกมที่ใช้) กับโค้ดเกมที่เกี่ยวข้อง รอบนี้ตั้งค่าให้เก็บทั้งหมดในการรันครั้งเดียว ไม่ต้องรันทีละหัวข้อ

== ต้องมีอะไรก่อนรัน ==
1. input/*.zip ที่มี .so จริง (arm64): libGTASA.so + libCheatMenu64.so (+ libSAUtils64.so ถ้ามี) — ใช้ zip เดิมได้ ถ้าไม่แก้ cache project จะถูกใช้ (เร็ว)
2. keywords.txt (ตั้งไว้แล้วสำหรับรอบนี้ ดูหัวไฟล์) ไม่ต้องแก้ก่อนรัน

== วิธีรัน ==
Actions > "Ghidra analyze" > Run workflow
  reanalyze = false (ใช้ cache ถ้า zip เดิม)  |  only = "libGTASA.so,libCheatMenu64.so" (ค่าเริ่มต้น ตัดไลบรารีอื่นออกให้เร็ว ; ว่าง = ทุกตัว)
ครั้งแรกที่ไม่มี cache วิเคราะห์ libGTASA ~22+ นาที ; ถ้ามี cache ทั้งงานน่าจะจบใน ~10-20 นาที
เสร็จแล้วโหลด artifact "ghidra-out" แล้วส่งทั้ง zip กลับมาให้ AI ที่ทำ ProMenu (ห้ามตัดไฟล์ทิ้ง)

== ผลลัพธ์ (out/<ไลบรารี>/) ==
- decompiled.named.c  ← อ่านไฟล์นี้เป็นหลัก : โค้ดถอดแล้ว + ชื่อสัญลักษณ์เกมจริงแทน FUN_/DAT_ ของ stub/ตัวแปรนำเข้า (เช่น CWaterLevel_GetWaterLevel, g_CTimeCycle_m_vRedGrade)

- imports.tsv : ตาราง FUN_/DAT_ -> mangled -> demangled (รวมที่อยู่แบบ base+offset ตรง ๆ ที่เมนูใช้กับข้อมูลเกมที่ไม่มีชื่อ symbol)
- byfunc.tsv : ฟังก์ชัน -> สตริงที่อ้างถึง (ไว้ดูว่าฟังก์ชันไหนคือหน้า/ฟีเจอร์ไหน เช่น 0x12f500 = GamePage)
- functions.tsv / symbols.tsv / strings.tsv / callers.tsv / callees.tsv / summary.txt , out/index.txt

== ไฟล์เหล่านี้อยู่ใน repo นี้ (แก้แล้วในรอบ 2026-10-25) ==
- scripts/ExportInfo.java : เพิ่ม @lib / @range / @0xOFFSET # คอมเมนต์ / fn:<ชื่อ> / @nocallers / @callees N  (คอมไพล์ตรวจกับ API จำลองแล้ว ; ยังไม่เคยรันกับ Ghidra จริงในรอบนี้)
- scripts/postprocess.py : ขั้นหลังรัน Ghidra (Python ล้วน, ทดสอบกับผลเดิมแล้ว) ; ถ้าพังไม่ทำให้ workflow ล้ม
- .github/workflows/ghidra.yml : input "only", MAX_DECOMP=4000, MAX_CALLERS=150, ขั้น postprocess ก่อนอัปโหลด
- keywords.txt : สร้างจาก symbols/strings ของผลรอบก่อน ; แก้เองได้ (บรรทัด # = คอมเมนต์)

== ข้อควรรู้เมื่ออ่านผล ==
- offset ทุกตัว = address - 0x100000 ; ชื่อ Ghidra FUN_00xxxxxx = address (offset + 0x100000)
- ฟังก์ชันหน้าเมนูมีตัวแปร/ฟิลด์เป็น this+offset (เช่น param_3 + 0x69 = checkbox SolidWater) ; อ่าน byfunc.tsv คู่กัน
- ถ้าต้องการฟังก์ชันเพิ่ม: เติม @0x.. หรือ fn:.. ใน keywords.txt แล้วรันซ้ำ (cache เดิม เร็ว) — แต่จุดประสงค์รอบนี้คือให้ครบในรอบเดียว
